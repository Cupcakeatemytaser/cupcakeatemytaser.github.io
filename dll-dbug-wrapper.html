Overview

When you have a DLL with no accompanying executable — whether it's a third-party library, a plugin, or a sample you're analysing — you need a wrapper EXE to load and call it. This guide walks through the complete process: from creating the project in Visual Studio 2026 to stepping through DLL code line by line in dnSpy.

Your DLL The compiled .dll file you want to debug
↓
Wrapper EXE Console app that loads and calls the DLL
↓
dnSpy Attach debugger, set breakpoints, step through
ℹ️

Architecture must match. If your DLL is x64, your wrapper must also target x64. A mismatch causes a BadImageFormatException at runtime.

01

Visual Studio 2026 Setup

Visual Studio 2026 introduces the Fluent UI redesign and deep GitHub Copilot integration. The project creation steps are the same as earlier versions — the dialogs just look cleaner.

  1. Create a Blank Solution

    Open VS 2026 → Create a new project → search Blank Solution → name it and click Create.

  2. Add a Console App project

    In Solution Explorer, right-click the solution → Add → New Project → search Console App (.NET Framework) → name it DebugWrapper.

  3. Select the correct framework

    Choose the same .NET Framework version as your DLL. To check your DLL's runtime, open it in dnSpy and read the header — it will say e.g. Runtime: .NET Framework 4.8.

  4. Set architecture to x64

    Right-click DebugWrapper → Properties → Build tab → set Platform target to x64. This must match the DLL architecture.

  5. Set as Startup Project

    Right-click DebugWrapper in Solution Explorer → Set as Startup Project. It goes bold to confirm.

⚠️

Console App (.NET Framework) vs Console App (.NET) — these are different. If your DLL targets .NET Framework 4.x, pick the Framework version. Mixing them causes load failures.

02

Inspect the DLL First

Before writing any code you need three things from the DLL: its namespace, its class name, and the method name you want to call. Open the DLL in dnSpy and check the header, then use the Object Browser in Visual Studio.

💡

Namespace = the building. Class = a room inside it. Method = the person in that room who does a job. You need all three to make a call.

Using the Object Browser in VS 2026

  1. Add a reference to the DLL first

    Right-click References (or Dependencies) → Add Reference → Browse → select your .dll file.

  2. Open Object Browser

    Go to View → Object Browser or press Ctrl+Alt+J.

  3. Expand your DLL

    In the left panel, expand your DLL → expand a namespace → expand a class → you'll see all methods listed. The ones starting with {} are your namespaces.

03

Build the Debug Wrapper

The wrapper is a console application that creates an isolated AppDomain, loads the DLL into it, finds your target class and method by name, then calls it. All output is captured so you can see exactly what happened at each step.

Replace YourFile.dll, NameSpace.Class, and YourMethod with the values you found using the Object Browser in Step 02.

Program.cs C# 
using System;
using System.IO;
using System.Reflection;

namespace DebugWrapper
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("=== Debug Wrapper Started ===");
            Console.WriteLine($"[*] Running from: {AppDomain.CurrentDomain.BaseDirectory}");

            try
            {
                // Create a new AppDomain with loadFromRemoteSources enabled
                AppDomainSetup setup = new AppDomainSetup
                {
                    ApplicationBase = AppDomain.CurrentDomain.BaseDirectory,
                    LoaderOptimization = LoaderOptimization.SingleDomain
                };

                // Set the config to allow remote sources
                AppDomain newDomain = AppDomain.CreateDomain(
                    "LoaderDomain",
                    null,
                    setup
                );

                string dllPath = Path.Combine(
                    AppDomain.CurrentDomain.BaseDirectory,
                    "YourFile.dll");  // ← replace with your DLL filename

                Console.WriteLine($"[*] Attempting to load: {dllPath}");
                Console.WriteLine($"[*] File exists: {File.Exists(dllPath)}");

                // Load the assembly by full path
                Assembly asm = Assembly.LoadFile(dllPath);
                Console.WriteLine($"[*] Assembly loaded: {asm.FullName}");

                // Find the class — use "Namespace.ClassName" format
                Type type = asm.GetType("NameSpace.Class");  // ← replace
                Console.WriteLine($"[*] Type found: {type}");

                // Find the method by name
                var method = type.GetMethod("YourMethod");  // ← replace
                Console.WriteLine($"[*] Method found: {method}");

                Console.WriteLine("[*] Calling YourMethod()...");
                method.Invoke(null, null);  // null = static method, null = no params
                Console.WriteLine("[*] YourMethod() completed successfully");
            }
            catch (Exception ex)
            {
                Console.WriteLine($"[!] Exception: {ex.GetType().Name}");
                Console.WriteLine($"[!] Message: {ex.Message}");
                if (ex.InnerException != null)
                {
                    Console.WriteLine($"[!] Inner Exception: {ex.InnerException.GetType().Name}");
                    Console.WriteLine($"[!] Inner Message: {ex.InnerException.Message}");
                }
                Console.WriteLine($"[!] Stack trace:\n{ex.StackTrace}");
            }

            Console.WriteLine("=== Debug Wrapper Finished ===");
            Console.ReadLine();
        }
    }
}

What each section does

CodeWhat it does
AppDomainSetupConfigures an isolated sandbox — sets the base folder and tells .NET not to share assemblies across domains
AppDomain.CreateDomain()Creates the sandbox named "LoaderDomain". Helps bypass Windows security blocks on DLLs from other machines
Assembly.LoadFile()Loads the DLL into memory by its full path. Use LoadFile not LoadFrom — LoadFrom triggers network location errors
asm.GetType()Finds a class inside the loaded DLL by its fully qualified name e.g. "MyNamespace.MyClass"
type.GetMethod()Finds a method by name inside that class. Returns a MethodInfo object describing it
method.Invoke(null, null)Calls the method. First null = static method (no instance needed). Second null = no parameters
ex.InnerExceptionThe underlying cause of an error — often more specific than the outer exception. Only printed if one exists
Console.ReadLine()Keeps the window open so you can read the output before it closes
✅

Static vs instance methods. If you get "cannot be accessed with an instance reference", the method is static. Change method.Invoke(null, null) — the first null is already correct for static. The error usually means you tried to create an instance with new ClassName() unnecessarily.

ℹ️

Three values to replace. Before running, replace YourFile.dll with your DLL filename, NameSpace.Class with the fully qualified class name from the Object Browser, and YourMethod with the method name you want to call.

04

Add the DLL Reference

  1. Open Add Reference dialog

    In Solution Explorer, right-click your project name → Add → Project Reference. Or use the top menu: Project → Add Reference.

  2. Browse to your DLL

    Click Browse (bottom left of the dialog) → navigate to your .dll file → click Add → OK.

  3. Confirm it appears

    Expand References (or Dependencies → Assemblies) in Solution Explorer — your DLL should appear there.

  4. Unblock the DLL if needed

    If the DLL came from another machine, Windows may block it. Right-click the file → Properties → tick Unblock → Apply. Or run in PowerShell: Unblock-File -Path "C:\path\to\file.dll"

⚠️

loadFromRemoteSources. If you see NotSupportedException: An attempt was made to load an assembly from a network location, add this to your App.config:

App.config XML 
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <startup>
    <supportedRuntime version="v4.0"
      sku=".NETFramework,Version=v4.8"/>
  </startup>
  <runtime>
    <loadFromRemoteSources enabled="true"/>
  </runtime>
</configuration>

Then make sure DebuggerWrapper.exe.config exists in your build output folder with the same content. If it doesn't appear automatically, add a post-build event:

Post-build event CMD 
copy "$(ProjectDir)App.config" "$(TargetDir)$(TargetName).exe.config"
05

Match the Framework Version

Your wrapper must target the same .NET Framework version as the DLL. A version mismatch is one of the most common causes of load failures.

How to check and change

  1. Check the DLL's runtime in dnSpy

    Open the DLL in dnSpy. The header at the top of Assembly Explorer shows Runtime: .NET Framework 4.8 (or whatever version it targets).

  2. Check your wrapper's framework

    Double-click your project in Solution Explorer to open the .csproj file. Look for <TargetFramework>.

  3. Change if needed

    Right-click project → Properties → Application tab → Target Framework → select the matching version. If it's not listed, install it via Visual Studio Installer → Individual Components → .NET Framework x.x targeting pack.

07

Debug with dnSpy

dnSpy can decompile .NET DLLs and let you set breakpoints directly inside them — even without source code. Combine it with your wrapper EXE to step through DLL code line by line.

  1. Open dnSpy and load the DLL

    Go to File → Open → select your .dll file. It appears in the Assembly Explorer on the left.

  2. Navigate to your target method

    In Assembly Explorer expand: YourDLL → Namespace → Class → Method. Double-click the method to open its decompiled source.

  3. Set a breakpoint

    Click in the left margin next to the first line of code inside the method. A red dot appears — this is your breakpoint inside the DLL.

  4. Start debugging via your wrapper

    Go to Debug → Start Debugging (Launch) → set Debug Engine to .NET Framework → browse to your DebugWrapper.exe → click OK.

  5. Step through the code

    When execution hits your breakpoint, use F10 to step over each line and F11 to step into function calls. Hover over any variable to inspect its value.

✅

Enable Just My Code — OFF. In Visual Studio go to Tools → Options → Debugging → General and uncheck "Enable Just My Code". This allows stepping into external DLL code.

Patching Methods in dnSpy

You can modify decompiled code on the fly to bypass checks or hardcode return values:

  1. Right-click the method → Edit Method (C#)

    A code editor opens with the decompiled source.

  2. Modify the code

    Replace the method body with your patched version — for example, return a hardcoded value instead of computing one.

  3. Click Compile then save

    Click Compile in the editor. Then go to File → Save Module to save the patched DLL to disk.

💡

Immediate Window tip. While paused on a breakpoint, type any expression in the Immediate Window and press Enter to evaluate it live — e.g. call a method, read a property, or compute a value using the current execution context.

🔒

Safety reminder. Always analyse unknown DLLs in an isolated VM with no network access. Even loading a DLL can trigger callbacks. Never run on your host machine.
